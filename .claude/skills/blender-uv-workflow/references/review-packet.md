# Standard UV review packet

A phase's machine HANDOFF remains the canonical asset contract. Present its
evidence to the owner in one report with the sections below; this is a view of
existing identities, not a second version registry. Use the same structure for
GPT, Claude and human review. Generate measurements from source data and reuse
unchanged pictures with provenance. Do not launch fresh bakes to fill the report.

1. **Status and identity.** Asset/revision, phase, source hash, saved/live state,
   what changed, what remains incomplete and exact files. Separate source,
   inspection scene and deployed version. A WIP is inspectable without a complete
   historical receipt chain; it does not pass freeze by having a report.
2. **All maps.** For every model, inventory every own page, shared atlas and
   protected texture dependency. Show readable full sheets plus detailed sections;
   include the preceding accepted chart sheet for comparison. Label worksheet
   sections as sections, not extra runtime pages. Keep actual positions, chart IDs,
   owner/member relationships and a material/family legend. Inventory retained UV
   layers separately so obsolete inputs cannot be mistaken for the current map.
3. **Resolution comparison.** Page dimensions, coordinate denominator, world/export
   units, per-component weaker/stronger-axis density, minimum and area-weighted
   percentiles. Compare against a measured relevant reference at the same scale;
   label ROI samples and missing references. Separately report texture-source
   detail and compression/mip validation, even if pending. Neither a bitmap's pixel
   count, model median nor an upscaled image proves window detail.
4. **Space accounting.** Count unique owned texels once. Keep all-face demand,
   owned filled area, bounding-box waste, worksheet gaps and final padding separate.
   Account for shared dependencies without charging a new copy per model. Show
   consumption by material/visibility and largest named owners. Consumed area is
   not automatically recoverable space. If demand exceeds capacity, say how far;
   do not run a packer or silently shrink to make the report green.
5. **Improvement proposals.** Exact specimen/region, measured footprint, expected
   net benefit or explicit unknown, compatibility risks, one bounded test and stop
   condition. Include unsuccessful experiments and their measured returns. Distinguish
   a savings upper bound from demonstrated net savings after replacement/padding.
6. **Learning and tracking.** For each confirmed lesson: evidence, proposed reusable
   rule, what measurement would catch recurrence. Track issue ID, stage, status,
   accountable next step and acceptance evidence. Include owner corrections,
   repeated failed work, elapsed time and actual paid calls; do not invent dollars.
7. **Bindings and coverage.** Per scope: active/editor UV, render-active UV, shader
   UV node, coordinate convention, texture resource/dimensions and face counts.
   A layer named UV_Final may contain raw pixel coordinates or a historical map.
   Protected props can legitimately use a different layer/denominator. Do not
   globally rename or switch them while fixing authored bindings. Final runtime
   bindings and texture detail remain freeze/export gates.

Before delivery, verify every model/resource has a picture and coverage entry,
all links exist, area totals reconcile, reference values trace to evidence and
the report does not label unknowns PASS. Inspect the generated charts at readable
size. State whether pictures are new renders, reused evidence or actual live
captures. Report packet validation proves completeness/identity, not visual quality.

Useful small machine outputs: map/layer inventory, density CSV, allocation CSV,
input hashes and issue tracker. Add validators only for demonstrated recurring
failures; this document does not require another orchestration layer, more agents
or an approval round for assembling a read-only WIP report.

**m. The fort filter uses the KB-limited state the palace lookup was explicitly repaired away from.** 8544 `cUnitStateAlive` vs 8554 `cUnitStateAny`, three lines apart. The palace code documents that exact trap at 7419–7425 and uses `cUnitStateAny` at 7431. If `fortCount` is 0, all four `fortPos` stay `cInvalidVector`, the guards at 8567–8570 never fire, and the two naval forts' own towers become live landing candidates. Also: only four positions are cached (8550–8553) with no loop.

**n. The "recover rather than wedge" branch (8271–8274) is unreachable, and would leak plans.** `gIstanbulLandShip` is written ≥0 only at 8826, immediately followed by 8829 `gIstanbulLandPhase = 1;`, and −1 only at 7250, immediately followed by 7251 `gIstanbulLandPhase = 0;`. So `phase > 0 && ship < 0` cannot occur. If it ever did, it does not call `istanbulLandingReset()`, and the next pass overwrites `gIstanbulLandShipPlan` (8775) and `gIstanbulLandArmyPlan` (8783), stranding a pri-100 reserve forever — the failure 7235–7237 warns about.

**o. The handoff loop mutates the roster it is iterating.** 8471 `for (n = 0; < aiPlanGetNumberUnits(gIstanbulLandArmyPlan, cUnitTypeLogicalTypeLandMilitary))` re-evaluates the bound every iteration while 8478 → 7407 `aiPlanAddUnit` moves the unit into a different plan. Compare 8291, where the count *is* cached first. If the transfer is immediate, roughly half the wave is skipped and 8480 then destroys the army plan with them still in it. Whether `aiPlanAddUnit` transfers within the tick: **UNKNOWN**.

**p. The STAGED hold never restores the idle interval.** 8832 set it to 3 s; 8394 returns without calling `xsSetRuleMinIntervalSelf(20)`. So while staged, the gun query (8316) re-runs and the entire gun fleet is re-tasked every 3 s — and the staged strike loop 8355–8368 has **no cap**, unlike the free-warship fallback which stops at 2 (8387).

**q. The gun check does not filter beaches.** It runs in phase 1 against the already-frozen `gIstanbulLandBeach` (8321) and can only delay the sail (8329) or hold indefinitely (8394). It is also `cPlayerRelationEnemyNotGaia` (8316), so a gaia-owned gun inside the 65 m ring never blocks anything.
